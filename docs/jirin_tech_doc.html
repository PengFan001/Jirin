1. 需求背景

1.1 业务痛点

Android 系统应用开发中，稳定性问题（JE/ANR/NE）的分析是一项高成本、高专业门槛的工作：

  • 问题分析需要深入理解 Android 源码和框架层机制
  • 日志分析流程复杂，需要多步骤关联分析
  • 责任归属判断需要丰富的经验积累
  • 同类问题反复出现，缺乏知识沉淀机制

1.2 目标

构建一个 AI Agent 工具，具备以下核心能力：

能力描述
自动化分析自动识别问题类型，调用专业 Agent 进行端到端分析
源码级知识内置 Android 源码级的 JE/ANR/NE 原理知识
责任归属准确判断问题责任方（App/SDK/System/Driver）
自学习从历史案例中学习，持续提升分析准确性
可扩展支持多 Agent 并行，支持导出为插件

4. 核心设计

4.1 状态管理 (AnalysisState)

使用 Pydantic 模型定义 Agent 间共享的状态，在 LangGraph 图中流转：

class AnalysisState(BaseModel):
    raw_log: str              # 原始日志
    detected_types: list      # 检测到的问题类型
    parsed_data: dict         # 解析后的结构化数据
    agent_results: dict       # 各 Agent 分析结果
    relevant_knowledge: list  # 检索到的知识
    similar_cases: list       # 相似历史案例
    final_report: str         # 最终报告

4.2 Orchestrator 分类机制

采用两阶段分类策略：

Phase 1: 规则匹配（快速、零成本）

使用正则表达式匹配日志特征模式，每种类型定义多个 pattern，达到阈值即判定。

Phase 2: LLM 分类（精确、处理边界情况）

当规则匹配不确定或检测到混合类型时，调用 LLM 进行精确分类。

4.3 Agent 基类设计

class BaseAgent(ABC):
    agent_name: str
    issue_type: IssueType
    
    @abstractmethod
    def get_system_prompt(self) -> str: ...
    
    @abstractmethod
    def build_analysis_prompt(self, state) -> str: ...
    
    async def analyze(self, state) -> AgentResult:
        # 1. 构建 prompt
        # 2. 注入知识库上下文
        # 3. 注入相似案例 (few-shot, 反馈感知)
        # 4. 注入 AOSP 源码路径上下文
        # 5. 调用 LLM
        # 6. 解析结构化结果

5.2 知识检索流程

Agent 分析时，系统自动检索相关知识：

  1. 根据问题类型检索对应的静态知识文档
  2. 使用日志内容在向量库中搜索相似历史案例
  3. 将检索结果作为上下文注入 Agent 的 Prompt

5.3 AOSP 源码搜索

采用双层架构，无需本地 AOSP 源码也能工作：

Tier 1: 内置知识层（始终可用）

预构建的 30+ 框架组件路径映射（AMS、Input、debuggerd 等）+ 5 条关键调用链（JE crash flow、ANR input/service/broadcast timeout、NE crash flow），Agent 分析时自动注入相关源码路径。

Tier 2: 本地源码层（可选配置）

配置 [source] aosp_source_dir 后，支持在本地 AOSP 源码树中搜索方法定义，提供更精确的代码级上下文。

5.4 用户反馈闭环

分析完成后可收集用户反馈（y/n/correction），存入 CaseStore：

  1. 正面反馈：标记案例为 "verified"，后续优先展示
  2. 负面反馈：记录原因，辅助改进
  3. 修正反馈：将用户纠正注入相似案例上下文，避免 LLM 重复犯错

6. 自学习机制

Reflector (反思器)

每次分析完成后，Reflector 调用 LLM 提取根因模式、关键指标、解决方案分类，形成结构化学习记录。

Classifier (分类器)

基于关键词匹配将根因归入预定义类别（如 null_pointer、lock_contention、jni_error 等），便于模式检索。

MemoryManager (记忆管理)

管理长期记忆，包括：

  • 纠错记录：用户纠正的错误分析，避免重复犯错
  • 强化记录：确认正确的分析，增强信心
  • 通用洞察：从分析中提炼的通用经验

7. 导出方案

导出的核心是将 知识库 + 分析流程 + Agent Prompt 打包，而非代码本身。

目标格式内容
QoderSKILL.md + assets/Agent prompt + 知识库摘要 + 分析流程
Cursor.cursor/rules/规则文件 + 分析指导
CodexAGENTS.md + jirin_knowledge/Agent 配置 + 知识库文档
通用Markdown 文档包知识库 + 方法论 + Agent prompts
