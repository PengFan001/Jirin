功能概览

Jirin 是一个专注于 Android 稳定性问题分析的 AI Agent 工具。它能自动识别日志类型，调用专业分析 Agent 进行深度分析，并输出结构化的分析报告。

⚠️

JE 分析

分析 Java Exception / Fatal Crash，定位异常类型、堆栈根因、责任方归属

⏳

ANR 分析

分析 Application Not Responding，识别主线程阻塞原因、锁竞争、系统资源问题

💥

NE 分析

分析 Native Exception / Tombstone，解读信号类型、backtrace、内存访问错误

🧠

自学习

从历史分析中学习模式，积累案例库，持续提升分析准确性

📦

插件导出

导出为 Qoder Skill / Cursor Rules / Codex AGENTS.md，可在多种 AI IDE 中使用

🛠

多模型支持

支持 OpenAI、Anthropic、Ollama 等多种 LLM 后端，灵活切换

📁

多平台日志

支持高通/MTK/展锐日志目录结构自动识别，支持目录学习记忆

📄

灵活输出

支持纯文本/Markdown/HTML 多种输出格式，MD 可直接导入飞书

🔄

MIXED 深度分析

混合问题类型时自动进行跨类型因果关联分析，确定因果链和修复优先级

💬

用户反馈闭环

分析后收集反馈，存入案例库，持续改进后续分析质量

📚

AOSP 源码引用

内置 30+ 框架组件路径映射，分析时自动引用 Android 源码关键路径

两种使用方式

Jirin 支持两种完全不同的使用方式，适用于不同场景。请根据你的需求选择：

方式 A

💻 安装为命令行工具（CLI 模式）

适用场景：需要完整 Agent 能力（LLM 调用、多 Agent 协作、自动学习）

工作方式：安装后在任意目录通过命令行运行，Jirin 会调用配置的 LLM 进行自动化分析

特点：

  • 完整的 Python Agent 运行时
  • 多 Agent 并行分析（LangGraph）
  • 自动学习 + 案例积累
  • 支持配置文件自定义 LLM
  • 安装一次，全局可用
方式 B

📝 导出为 IDE 知识插件（插件模式）

适用场景：在 Cursor / Codex / Qoder 等 AI IDE 中分析日志

工作方式：将 Jirin 的专业知识导出为规则文件，AI IDE 中的模型会"像 Jirin 一样分析"

特点：

  • 导出的是知识 + 方法论，不是 Python 运行时
  • 使用 IDE 自带的模型（如 ChatGPT 5.5）
  • 无需安装 Python 环境
  • 无需配置 API Key
  • AI IDE 自动加载，无需额外配置

两种方式的核心区别

对比项方式 A：CLI 安装方式 B：导出到 IDE
运行环境本机 Python 环境AI IDE（Cursor/Codex/Qoder）
使用的 AI 模型用户配置的 LLM（OpenAI/Ollama 等）IDE 自带的模型（如 ChatGPT 5.5）
是否需要 API Key是（除非用本地 Ollama）否（IDE 已处理）
是否有自动学习能力是否（知识固定）
分析能力来源Jirin 完整 Agent 管线AI 模型 + Jirin 知识上下文
安装复杂度需要 Python 3.11+复制文件即可
使用方式命令行 jirin analyze <日志>在 IDE 聊天中直接贴日志
关键理解：导出到 Cursor/Codex 后，用户使用的是 IDE 自己的 AI 模型（比如 ChatGPT 5.5）。Jirin 的导出文件是专业知识和分析方法论，AI 模型会读取这些知识后"变成"一个 Android 稳定性分析专家。这个过程是自动的——只要文件放在正确位置，IDE 会自动加载。

安装配置（方式 A：CLI 模式）

仅在使用 CLI 模式时需要以下步骤。如果你选择方式 B（导出到 IDE），无需安装，直接导出文件即可。

python --version  # 确认版本 >= 3.11

卸载 Jirin

如果不再需要使用 Jirin，执行以下命令即可完全卸载：

# 卸载 Jirin 包
pip uninstall jirin -y

# （可选）删除项目目录
# rm -rf /path/to/Jirin  # Linux/Mac
# Remove-Item -Recurse -Force Jirin  # Windows PowerShell

卸载后，jirin 命令将不再可用。配置文件和数据文件（data/ 目录）不会被自动删除，如需清理请手动删除。

LLM 接入指南

Jirin 通过 LiteLLM 统一调用各种 LLM 服务。所有支持 OpenAI 兼容 API 格式的模型都可以接入。

配置方法

编辑 config/settings.toml 中的 [llm] 部分。核心字段：

字段说明示例
provider调用方式（大多数国产模型用 "openai"）"openai"
model模型名称"deepseek-chat"
api_keyAPI 密钥"sk-xxx"
api_baseAPI 地址（非 OpenAI 官方地址时需要）"https://api.deepseek.com/v1"

各模型接入配置

OpenAI (GPT-4o / GPT-4.1)

[llm]
provider = "openai"
model = "gpt-4o"
api_key = "sk-xxx"
# api_base 不需要填，默认使用 OpenAI 官方地址

Anthropic (Claude)

[llm]
provider = "anthropic"
model = "claude-sonnet-4-20250514"
api_key = "sk-ant-xxx"

DeepSeek V4 Pro

[llm]
provider = "openai"
model = "deepseek-chat"
api_key = "sk-xxx"
api_base = "https://api.deepseek.com/v1"
DeepSeek 的 API 格式与 OpenAI 完全兼容，只需将 api_base 指向 DeepSeek 的地址即可。在 DeepSeek 开放平台 获取 API Key。

通义千问 (Qwen)

[llm]
provider = "openai"
model = "qwen-plus"
api_key = "sk-xxx"
api_base = "https://dashscope.aliyuncs.com/compatible-mode/v1"
通义千问通过阿里云灵积（DashScope）提供 OpenAI 兼容 API。可用模型包括 qwen-plus、qwen-max、qwen-turbo 等。在 阿里云控制台 获取 API Key。

Kimi K3 (Moonshot)

[llm]
provider = "openai"
model = "kimi-k3"
api_key = "sk-xxx"
api_base = "https://api.moonshot.cn/v1"
Kimi 由月之暗面（Moonshot AI）提供。在 Moonshot 开放平台 获取 API Key。

Ollama 本地模型（免费，无需 API Key）

[llm]
provider = "ollama"
model = "qwen2.5:14b"
api_base = "http://localhost:11434"
Ollama 使用步骤：
1. 安装 Ollama：https://ollama.com/
2. 拉取模型：ollama pull qwen2.5:14b
3. 确认服务运行：ollama list
4. 配置 Jirin 的 settings.toml 如上

配置验证

配置完成后，运行以下命令验证：

# 准备一个简单的测试日志文件
echo "FATAL EXCEPTION: java.lang.NullPointerException" > test.log

# 运行分析，如果成功说明 LLM 配置正确
jirin analyze test.log --verbose

如果配置有误，Jirin 会在启动时给出友好提示，告诉你哪个配置项需要检查。

完整命令参考

安装后，可在任意目录通过 jirin 命令使用。以下列出所有可用命令：

核心命令：分析日志

# 分析单个日志文件（文件路径）
jirin analyze crash.log

# 分析日志目录（目录路径，自动识别平台结构）
jirin analyze /path/to/logs/

# 指定配置文件
jirin analyze crash.log --config /path/to/settings.toml

# 详细模式（显示分析过程）
jirin analyze crash.log --verbose

# 导出 Markdown 报告（可导入飞书）
jirin analyze crash.log --export md

# 导出 HTML 报告
jirin analyze crash.log --export html

# 保存报告到文件（根据扩展名自动识别格式）
jirin analyze crash.log --output report.md
jirin analyze crash.log --output report.html
jirin analyze crash.log --output report.txt

# 组合使用：分析目录 + 详细模式 + 保存 MD 报告
jirin analyze /path/to/logs/ --verbose --output analysis_report.md

# 跳过分析后的反馈提示（批量场景）
jirin analyze crash.log --no-feedback

analyze 参数一览

参数说明是否必须
<log_path>日志文件路径或日志目录路径必须
--config, -c配置文件路径（默认 config/settings.toml）可选
--verbose, -v显示详细分析过程可选
--export, -e导出格式：none（默认）/ md / html可选
--output, -o保存报告到文件（自动识别格式）可选
--interactive/--no-feedback启用/禁用分析后反馈提示（默认启用）可选

导出与 IDE 集成（方式 B：插件模式）

如果你不想安装 CLI，或者更习惯在 AI IDE 中工作，可以将 Jirin 的专业知识导出为 IDE 插件。

导出后如何使用？

导出后，你只需要在 AI IDE 中直接贴日志或描述问题，AI 会自动参考 Jirin 的知识进行分析。无需额外配置，IDE 会自动加载规则文件。

各 IDE 导出与使用方式

🟢 Cursor

# 1. 导出 Cursor Rules
jirin export cursor --output ./.cursor/rules

# 2. 将 .cursor/rules/ 目录复制到你的项目根目录
# 3. 打开 Cursor，在 Chat 中直接贴入日志：
#    "帮我分析这个 ANR 日志：[粘贴日志内容]"
Cursor 中如何使用：Cursor 会自动读取 .cursor/rules/ 中的规则文件。你在 Cursor 的 Chat 中（可以使用 ChatGPT 5.5 或任何 Cursor 支持的模型）直接粘贴日志，Cursor 会按照 Jirin 的方法论进行分析。不需要运行任何 Python 命令，所有分析由 Cursor 的 AI 模型完成。

🔵 OpenAI Codex

# 1. 导出 Codex AGENTS.md
jirin export codex --output ./codex_config

# 2. 将 AGENTS.md 和 jirin_knowledge/ 复制到你的项目根目录
# 3. 在 Codex 中提问时，它会自动读取 AGENTS.md 中的知识
Codex 中如何使用：Codex 会自动读取项目根目录的 AGENTS.md 文件作为上下文。你在 Codex Chat 中（使用 ChatGPT 5.5 或其他模型）直接提问即可。Jirin 的专业知识会作为 AI 的背景知识自动生效。

🔬 Qoder

# 1. 导出 Qoder Skill
jirin export qoder --output ./my_skill

# 2. 将 my_skill/ 目录复制到 .qoder/skills/
# 3. 在 Qoder 中使用 /jirin 命令触发分析

总结：无论使用哪种 IDE，导出后用户都使用 IDE 自己的 AI 模型（如 ChatGPT 5.5）。Jirin 提供的是专业知识和分析方法论，AI 模型读取这些知识后就能进行专业级分析。整个过程是自动的——只要文件放在正确位置，不需要额外配置。

MIXED 深度分析：当检测到多种问题类型（如 JE + ANR）时，系统会自动经过 Correlator 节点进行跨类型因果关联分析，确定因果链、根本原因和修复优先级，而非简单并列展示各类型的分析结果。
用户反馈：分析完成后，CLI 会询问分析结果是否有帮助。你可以选择“是”、“否”或提供“修正”。反馈会存入案例库，后续分析时会优先参考有正面反馈的案例，并避免已修正过的错误。

跨机器部署

如果需要在另一台电脑上安装 Jirin，有两种方式：

方式一：复制整个项目目录

复制 Jirin 目录将整个 Jirin 文件夹复制到目标机器（U 盘、网络共享、git 等均可）
# 例如打包为 zip
cd /path/to/Jirin
# Windows: 压缩 Jirin 文件夹
# Linux/Mac: tar -czf jirin.tar.gz Jirin/
目标机器环境准备确保目标机器已安装 Python 3.11+
python --version  # 确认 >= 3.11
安装并配置
cd Jirin
pip install -e .

# 复制配置模板并填入 API Key
cp config/settings.example.toml config/settings.toml
# 编辑 settings.toml，填入 API Key

方式二：通过 Git 获取代码

# 在目标机器上 clone 仓库
git clone <repository-url> Jirin
cd Jirin
pip install -e .

# 配置 LLM
cp config/settings.example.toml config/settings.toml
注意：每台机器都需要独立执行 pip install -e . 安装步骤，并各自配置 config/settings.toml（包含 API Key）。data/ 目录中的学习数据（案例库、记忆）可以一并复制，也可以在新机器上从零开始积累。

注意事项

CLI 模式需要 LLM 配置：首次使用 CLI 前必须配置 LLM API Key。如果使用本地模型（Ollama），请确保 Ollama 服务已启动。插件模式无需配置。
日志输入支持文件和目录：jirin analyze 的参数既可以是单个日志文件路径，也可以是日志目录路径。目录模式下会自动识别高通/MTK/展锐平台结构。
多平台支持：支持高通、MTK、展锐三大平台的日志目录结构自动识别。遇到新结构时，可使用 jirin learn-structure 命令教工具学习。
飞书集成：使用 --export md 或 --output report.md 生成的报告可直接导入飞书文档。
插件模式使用 IDE 模型：导出到 Cursor/Codex 后，分析由 IDE 的 AI 模型完成（如 ChatGPT 5.5），不需要安装 Python 或配置 API Key。
隐私安全：使用云端 LLM 时请注意数据安全；如有顾虑，CLI 模式可使用本地模型（Ollama），插件模式取决于 IDE 的隐私策略。
持续改进：CLI 模式分析完成后，系统会自动提示反馈。直接回复 y/n/c 即可帮助系统学习。也可使用 jirin learn feedback 命令手动添加反馈。
AOSP 源码搜索：系统内置 30+ Android 框架组件路径映射，分析时自动引用相关源码路径。如需深度搜索，可在 config/settings.toml 中配置 [source] aosp_source_dir 指向本地 AOSP 源码目录。
